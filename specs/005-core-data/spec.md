# Feature Specification: shared/ crate — data layer (manifest, cache trait, license, Bundle, discovery)

**Feature Branch**: `005-core-data`

**Created**: 2026-06-22

**Status**: Draft

**Input**: User description: "Split into `005-core-data` (types + cache trait + license + parsers) and `006-core-renderer` (wgpu pipelines + draw_frame)." This is the first half: the data-and-types layer of the new `shared/` workspace member, sized to unblock 003-web-client (FR-017 through FR-029 + the §Assumptions reference to `shared::artifact`) and 004-ios-client (FR-008 through FR-014 + §Assumptions). The renderer + projection + hit_test surface lands in 006-core-renderer, stacked on this branch.

## Clarifications

### Session 2026-06-22

- Q: How does `Bundle` expose its geometry data? → A: `Bundle` holds an eagerly-parsed `FlatGeobufReader` (the reader + R-tree spatial index). `FlatGeobufReader` + `open_flatgeobuf_reader(bytes)` are owned by 005 (this feature), not 006. 006's renderer consumes `bundle.geometry_reader` directly for vertex upload + spatial-index hit-testing.
- Q: Should `Bundle` hold an open SQLite `Connection` at all? → A: No. `Bundle` is pure parsed data: `Manifest` + `FlatGeobufReader` + `BTreeMap<StatisticShardKey, Vec<u8>>` (raw shard bytes, filtered by `DistributionContext::authorized_classes` at open time) + `DistributionContext`. `Bundle: Send + Sync`. The renderer (006-core-renderer) opens its own thread-local `rusqlite::Connection` against `bundle.shard_bytes` and `ATTACH`'s the authorized shards; on hot-swap the renderer drops + reopens. This decouples bytes (which the loader produces on any thread) from the connection (which the renderer owns on its own thread) and lets `Arc<Bundle>` cross the watch channel cleanly without `!Send` complications.
- Q: Should the consumer-side `Manifest` validate a `manifest_schema_version` field? → A: Yes. Add `manifest_schema_version: u32` to the manifest; v1 = `1`; the producer's `write_manifest` always emits it; `parse_manifest` rejects unknown versions with a typed `AppError`. Same pattern as `parse_discovery_document`. Forward-compat gate for v2+ shape changes; cheap now, expensive to retrofit when an old iOS install hits a v2 manifest in the field.
- Q: Should `parse_manifest` / `parse_discovery_document` cap input size to defend against oversize / adversarial inputs? → A: No. Not a concern at this layer. The platform fetch adapter imposes practical bounds (web `fetch()` Content-Length checks; iOS `URLSession` defaults); a malformed-but-large manifest produces SHA-256 verification failures on the shards it references downstream. If a real OOM / DoS scenario surfaces operationally, add the cap then.
- Q: How does `Bundle::open` resolve the manifest source across web (OPFS) and native (filesystem)? → A: It doesn't — the `ArtifactCache` trait IS the cross-platform "where do bytes live" abstraction. `Bundle::open(version_label: &str, cache: &dyn ArtifactCache, distribution_context: DistributionContext) -> Result<Bundle, AppError>` reads the manifest via `cache.get(version_label, "manifest.json")`; geometry + shards likewise. No path argument; no cfg-gated reinterpretation. The platform shell ensures the cache can serve the requested `version_label` — on web this happens naturally (the loader fetched bytes into OPFS); on iOS the startup flow either pre-populates the cache from `Bundle.main`'s `Resources/embedded_artifacts/` or the cache implementation falls back to the app bundle's Resources for the embedded version_label.

## Scenarios & Testing *(mandatory)*

### Workspace member with extracted producer types (P1)

It compiles cleanly for the host target (`cargo build -p shared`) and for `wasm32-unknown-unknown` (`cargo build -p shared --target wasm32-unknown-unknown`). **Acceptance Scenarios**:

3. **Given** the same checkout, **When** the developer runs `cargo test -p ingestion`, **Then** every pre-existing ingestion test (including the manifest-determinism, license-class, statistic-kind tests) passes against the moved types reached via `shared::*`.
4. **Given** the post-move state, **When** any developer greps for `pub use shared::` inside `ingestion/`, **Then** they find NONE for the moved types — ingestion does not forward shared's types through re-exports; every `crate::canonical::*` / `crate::artifact::*` site that referenced a moved type was migrated to the corresponding `shared::` path directly.

### Manifest parsing (consumer side) (P2)

`shared::artifact::manifest::parse_manifest(bytes: &[u8]) -> Result<Manifest, AppError>` parses a byte slice produced by `ingestion::artifact::writer::manifest::write_manifest` into a strongly-typed consumer-side `Manifest` value. Round-trip property: bytes produced by the producer side parse into a `Manifest`; that `Manifest`'s `relative_path` / `size_bytes` / `sha256` fields exactly match what the producer wrote. Malformed input (missing field, wrong type, unknown statistic_code) returns a typed `AppError` whose message identifies what failed to parse; the function never panics on adversarial input. This is the contract `client.md` §Manifest schema (consumer view) locks in.

**Acceptance Scenarios**:

1. **Given** a manifest written by `ingestion::artifact::writer::manifest::write_manifest` against a fixture set (one geometry shard + two statistic shards across two license classes), **When** `parse_manifest` parses the bytes back, **Then** the resulting `Manifest` exposes `manifest_schema_version` (= `1` for v1), `version`, `artifact_created` (parsed as `chrono::DateTime<chrono::Utc>`), `geometry: ManifestEntry`, `statistics: BTreeMap<StatisticKind, BTreeMap<LicenseShardClass, ManifestEntry>>`, `source_revisions: BTreeMap<DataSourceKind, SourceRevision>`; every field matches the producer-side input.
2. **Given** a manifest with `manifest_schema_version: 2` (a future shape change), **When** `parse_manifest` runs, **Then** the result is `Err(AppError)` whose message contains the literal `"unknown manifest_schema_version 2"`; the function does NOT continue parsing the rest of the document.
3. **Given** a manifest with an unknown statistic code (`"unknown_stat"` instead of `"tfr"`), **When** `parse_manifest` runs, **Then** the result is `Err(AppError)` whose message contains the literal `"unknown_stat"` (so the operator can identify the offending key); the function does NOT panic.
4. **Given** a manifest with a malformed `sha256` field (length != 64 hex chars), **When** `parse_manifest` runs, **Then** the result is `Err(AppError)` whose message names the offending entry's relative_path.
5. **Given** any well-formed manifest produced by the post-move `write_manifest`, **When** `parse_manifest(bytes)` runs and then the result is re-serialized via the same `Manifest` `Serialize` impl, **Then** the re-serialized bytes are byte-equal to the input (the consumer-side parse round-trips through the producer-side serializer; this verifies the type-shape match across the producer / consumer halves on v1 manifests).

### `ArtifactCache` trait + cross-platform cache contract (P3)

`shared::artifact::cache::ArtifactCache` is the cross-platform cache trait that both `web/src/cache.rs::OpfsArtifactCache` (consumed by 003-web-client) and `ios/EaforaApp/FileSystemArtifactCache.swift` (consumed by 004-ios-client) implement. Surface per `client.md` §Fetch / cache / load pipeline + the trait signatures referenced in `client-web.md` §OPFS cache adapter and `client-ios.md` §Implementation: FileSystemArtifactCache.swift. The trait is defined once in `shared/`; per-platform implementations satisfy it; the `shared::artifact::Bundle` loader consumes the trait by reference (no platform-specific code inside `shared::artifact::Bundle`). The trait is `async` (each function returns a `Future`); `Send` / `Sync` bounds are NOT required (single-threaded WASM uses it without locks).

**Acceptance Scenarios**:

1. **Given** `shared/src/artifact/cache.rs` defines `pub trait ArtifactCache` with `async fn put(...) -> Result<(), AppError>`, `async fn get(...) -> Result<Option<Vec<u8>>, AppError>`, `async fn list_versions(...) -> Result<Vec<String>, AppError>`, `async fn delete_version(...) -> Result<(), AppError>`, **When** a test crate implements the trait against an in-memory `HashMap`-backed mock, **Then** `Bundle::open` (FR-019) consumes the mock as `&dyn ArtifactCache` and the test exercises a complete round-trip without invoking any per-platform code.
2. **Given** the trait definition, **When** any consumer attempts to use it from a `Send + Sync` context, **Then** the compiler does NOT enforce `Send + Sync` (web's `OpfsArtifactCache` holds `!Send` `JsValue` handles indirectly; the trait must be usable in single-threaded WASM without the bound).
3. **Given** the trait's function signatures, **When** the iOS and web spec's per-platform adapter implements the trait, **Then** the implementation requires no async-trait crate (Rust 1.75+ stable AFIT — async fn in trait — is available; verify against the workspace's Rust edition / rustc per the §Assumptions).

### Discovery document type + parse (P4)

`shared::artifact::discovery::DiscoveryDocument` is the deserialized form of the JSON at `https://eafora.org/discovery` defined in `client.md` §Discovery document shape. The struct has fields `schema_version: u32`, `repository_base_url: String`, `minimum_client_version: String`, `sunset: Option<String>` and implements `serde::Deserialize`. A `parse_discovery_document(bytes: &[u8]) -> Result<DiscoveryDocument, AppError>` helper validates `schema_version == 1` and returns the parsed document; unknown `schema_version` returns a typed `AppError` (per `client.md` step "Clients reject documents whose `schema_version` they don't recognize, falling back to their baked-in defaults"). This struct is what both 003-web-client (FR-027) and 004-ios-client (FR-026) consume.

**Acceptance Scenarios**:

1. **Given** a discovery JSON document matching the schema in `client.md` §Discovery document shape, **When** `parse_discovery_document` parses the bytes, **Then** the resulting struct's fields match the JSON exactly.
2. **Given** a discovery JSON with `schema_version: 2`, **When** `parse_discovery_document` parses the bytes, **Then** the result is `Err(AppError)` whose message contains the literal `"unknown schema_version 2"` so the caller can fall back to its baked-in defaults per the documented protocol.
3. **Given** a discovery JSON with `sunset: "2027-01-01T00:00:00Z"`, **When** `parse_discovery_document` parses the bytes, **Then** the result's `sunset` is `Some("2027-01-01T00:00:00Z".to_string())`; the type does NOT parse this as `chrono::DateTime` at this layer — the caller decides how to compare against `now()` per the consumer-controlled fallback logic.
4. **Given** a discovery JSON missing the `sunset` field entirely, **When** `parse_discovery_document` parses the bytes, **Then** `sunset` is `None` (the field is `Option<String>` per the schema's `null in steady state` rule).

### `Bundle` loader + hot-swap channel (P5)

`shared::artifact::Bundle::open(version_label: &str, cache: &dyn ArtifactCache, distribution_context: DistributionContext) -> Result<Bundle, AppError>` opens a complete artifact bundle for the requested `version_label` by reading every file via the supplied cache (`cache.get(version_label, "manifest.json")` for the manifest; `cache.get(version_label, &entry.relative_path)` for each shard + geometry). The `ArtifactCache` trait is the cross-platform "where do bytes live" abstraction — on web it resolves into OPFS; on iOS it resolves into `Library/Caches/artifacts/` or (for the embedded `version_label`) into `Bundle.main`'s `Resources/embedded_artifacts/` per the platform shell's cache implementation. `Bundle::open` does NOT touch the filesystem directly; no path argument; no cfg-gated reinterpretation. It validates every referenced shard's SHA-256 against `shared::filesystem::verify_sha256`, eagerly parses the geometry bytes into a `FlatGeobufReader` (per FR-020a), and loads the byte buffers for every license shard this distribution context is authorized to access per `shared::license::DistributionContext::authorized_classes` (FR-022) into `shard_bytes`. The `Bundle` is pure parsed data: `Manifest` + `FlatGeobufReader` + `BTreeMap<StatisticShardKey, Vec<u8>>` + `DistributionContext`. `Bundle: Send + Sync` so the renderer's `tokio::sync::watch::Sender<Arc<Bundle>>` carries it across threads (iOS loader on a tokio worker; web loader on the single WASM thread). The SQLite `Connection` is NOT part of `Bundle`; the renderer (006-core-renderer) opens its own thread-local connection against `bundle.shard_bytes` and `ATTACH`'s the authorized shards on construction + on hot-swap. Bundle hot-swap happens via `Sender::send(Arc<new_bundle>)` per `client.md` §Bundle hot-swap. The watch-channel types are exported from `shared` (FR-023) so both clients use the cross-platform shape.

**Acceptance Scenarios**:

1. **Given** a populated `MockArtifactCache` carrying a manifest + matching shard bytes for `version_label = "2026-06-22+ada"`, **When** `Bundle::open("2026-06-22+ada", &cache, DistributionContext::FirstParty)` runs, **Then** the result is `Ok(Bundle)`; the bundle's `shard_bytes` map contains an entry for every base + non-commercial + share-alike shard the manifest references; every shard's bytes were SHA-256-verified during open; the geometry bytes are parsed into `bundle.geometry_reader`.
2. **Given** a manifest references a shard whose actual bytes don't match the recorded SHA-256, **When** `Bundle::open` runs, **Then** the result is `Err(AppError)` whose message identifies the mismatched `relative_path` and both the expected + actual SHA-256 prefixes (first 8 hex chars each); the partially-populated `shard_bytes` map is dropped cleanly (no leaked bytes in memory after the error returns).
3. **Given** a `DistributionContext::Embedded` context, **When** `Bundle::open` runs against the same `version_label` as scenario 1, **Then** only the `Base` license shards land in `shard_bytes`; the non-commercial and share-alike shards are not loaded into memory (saves both I/O and RAM for the embedded context where they wouldn't render anyway).
4. **Given** an `Arc<Bundle>` published via `tokio::sync::watch::Sender::send(new_arc)`, **When** the matching `Receiver` calls `Receiver::borrow_and_update()`, **Then** the returned guard exposes the new bundle; the previous `Arc` is dropped when its last in-flight query completes (per `client.md` §Bundle hot-swap: "in-flight queries holding an old `Arc` finish against the old bundle, and the old bundle's memory frees when the last reference drops").
5. **Given** a `shared::filesystem::sha256_hex(bytes: &[u8]) -> String` function (moved from the former `ingestion::filesystem::sha256_hex`), **When** any consumer calls it on a known input, **Then** the returned hex matches the same 64-char lowercase hex the producer side already emits (verified against the existing producer-side tests).
6. **Given** a `Bundle` value held in an `Arc`, **When** any thread asserts `Arc<Bundle>: Send + Sync`, **Then** the compiler accepts it (the `Bundle` struct has no `!Send` or `!Sync` fields). The watch channel's `Sender::send(Arc<Bundle>)` works from any thread, including tokio worker threads on native and the single WASM thread on web.

### License authorization (P6)

`shared::license::DistributionContext` enum + `authorized_classes(self) -> &'static [LicenseShardClass]` function per the exact sketch in `client.md` §Attaching license shards. v1 ships two distribution-context variants: `FirstParty` (authorized for `[Base, NonCommercial, ShareAlike]`) and `Embedded` (authorized for `[Base]` only). The function returns a `&'static` slice; adding a new `LicenseShardClass` variant elsewhere in `shared/` produces a compile error in every `DistributionContext` arm until each arm is updated explicitly (Rust's non-exhaustive-match enforcement); the spec's "neither addition is silent" property per `client.md` is structurally satisfied.

**Acceptance Scenarios**:

1. **Given** `DistributionContext::FirstParty`, **When** `authorized_classes()` is called, **Then** the returned slice is `&[LicenseShardClass::Base, LicenseShardClass::NonCommercial, LicenseShardClass::ShareAlike]`.
2. **Given** `DistributionContext::Embedded`, **When** `authorized_classes()` is called, **Then** the returned slice is `&[LicenseShardClass::Base]` only.
3. **Given** a new `LicenseShardClass` variant added to the enum, **When** a developer attempts to compile without updating every `DistributionContext` arm in `authorized_classes()`, **Then** `cargo check -p shared` fails with a non-exhaustive match error pointing at the function; the compiler is the failure mode that catches the missing arm.

### Edge Cases

- **Manifest references a shard the cache doesn't have** — `Bundle::open` calls `cache.get(version_label, relative_path)` and receives `Ok(None)`. The function returns `Err(AppError)` whose message names the missing relative_path; the caller is expected to fetch the shard via the platform's fetch adapter (003 FR-025 / 004 FR-025) and call `Bundle::open` again. This spec does NOT include the fetch-then-retry orchestration — that lives in the platform shells.
- **Manifest's `artifact_created` is in the future** — parsed successfully (it's just a timestamp); no validation. The producer is the source of truth; if it produced a future timestamp, the consumer trusts it.
- **A manifest entry's `relative_path` contains `..` or absolute path** — `Bundle::open` MUST reject the manifest with an `AppError` whose message names the offending entry. Path traversal across cache subdirectories is a security concern; rejecting at parse time is cheap.
- **Concurrent `Bundle::open` calls against the same cache** — the cache trait's `get` returns owned bytes per call; two simultaneous opens against the same cache are safe at this layer. Each `Bundle::open` produces an independent `Bundle` value; the renderer's `watch::Sender` decides which becomes current.
- **WASM target requires SQLite via `Vec<u8>`-backed VFS** — per `client.md` §SQLite in the client, the web client downloads the whole shard as a `Vec<u8>` and queries in memory via a custom VFS. The VFS implementation lives in `shared/` per `client.md` §Module layout (`shared::sqlite::vfs`). This spec provides the VFS module (FR-020); the actual connection-opening that uses it happens in 006-core-renderer's renderer thread against `bundle.shard_bytes[(statistic_kind, license_shard_class)]`. On non-wasm32 targets, SQLite reads from the in-memory bytes via the same VFS pattern (no special-case file-path open needed — `bundle.shard_bytes` lives in memory regardless of target).
- **FlatGeobuf bytes are partially downloaded** (consumer scenario) — the SHA-256 verification step fails because the byte count doesn't match the expected `size_bytes`; `Bundle::open` returns an error. The cache layer is responsible for not handing partial bytes to the bundle loader; this is checked at the SHA-256 layer regardless.

## Requirements *(mandatory)*

### Functional Requirements

#### Workspace + crate structure

- **FR-001**: System MUST add a `shared/` Cargo workspace member at the workspace root. `shared/Cargo.toml` declares `[package]` with `name = "shared"`, `edition = "2024"`, `version = "0.0.0"` (matches the placeholder versioning convention from `.specify/memory/constitution.md` §Versioning); the workspace root `Cargo.toml`'s `members` array gains `"shared"`. The crate is a library crate (`[lib]`); no `[[bin]]` targets.
- **FR-002**: System MUST organize `shared/src/` per `docs/architecture/client.md` §Module layout: `lib.rs` (declares submodules + re-exports); per-feature module directories (`artifact/`, `hashing/`, `sqlite/`, `statistic/`, `license/`); `mod.rs` files in each subdirectory hold ONLY `pub mod ...; pub use ...::*;` per the `mod.rs holds only declarations` rule; primary module content lives in named files inside each directory.
- **FR-003**: System MUST compile cleanly for `cargo build -p shared` against the host (Mac mini M1, Apple Silicon) and for `cargo build -p shared --target wasm32-unknown-unknown` against the web target. Code that can't compile to wasm32 (filesystem operations that don't exist in WASM; tokio runtime features not available single-threaded) MUST be `#[cfg(not(target_arch = "wasm32"))]`-gated. The `shared/Cargo.toml` MUST declare `[target.'cfg(target_arch = "wasm32")'.dependencies]` and `[target.'cfg(not(target_arch = "wasm32"))'.dependencies]` blocks to isolate target-specific dependencies (no `js-sys` / `web-sys` outside wasm32; no tokio `rt-multi-thread` inside wasm32).
- **FR-004**: System MUST register dependencies via the workspace's `[workspace.dependencies]` table where the dep is shared with ingestion (`serde`, `serde_json`, `chrono`, `uuid`, `sha2`, `rusqlite`, `flatgeobuf`, `geozero`, `geo-types`, `minimer`, `log`, `tokio` with reduced features for cross-platform use). Per-target deps (WASM-only: `wasm-bindgen`, `wasm-bindgen-futures`, `js-sys`, `web-sys`; non-wasm32: nothing new for this feature) go in the per-target dependency tables.

#### Type extraction from `ingestion/`

- **FR-005**: System MUST move the following types from `ingestion/src/canonical/canonical_model.rs` to `shared/src/canonical/canonical_model.rs`:
  - **Enums + value types** (pure, no Postgres wire shape): `StatisticKind` (enum + `code()` + `TryFrom<&str>`), `DataSourceKind` (enum + `code()` + `TryFrom<&str>`), `DataStatus` (enum + `as_str()` + `TryFrom<&str>`), `LicenseClass` (enum + `as_str()` + `TryFrom<&str>`), `LicenseShardClass` (enum + `from_license_class()` + `as_str()` + `TryFrom<&str>`), `SourceRevision` (struct, derives `Serialize` + `Deserialize` + `Clone`).
  - **Consumer-side Models** (the Model half of the Model + Entity pair per `docs/conventions/types.md`): `Region`, `Country`, `Statistic`, `DataSource`. Consumers need these for: region-detail UI (`Region.name_en`, `Region.level`, `Region.parent_region_id` parent-chain rendering); FlatGeobuf-feature-to-region join (`Country.iso3` → `Region.id`); statistic-picker + detail-panel display (`Statistic.name_en`, `Statistic.units`, `Statistic.description`); source-panel attribution (`DataSource.name_en`, `DataSource.homepage_url`, `DataSource.license_name`, `DataSource.attribution_text`).
  - The matching **`*Entity` wire-shape types** (`RegionEntity`, `CountryEntity`, `StatisticEntity`, `DataSourceEntity`) STAY in `ingestion/src/canonical/canonical_model.rs` — they're Postgres-shaped projections only the producer's sqlx queries construct. The `From<Entity> for Model` / `TryFrom<Entity> for Model` impls live next to the Entity (in ingestion) per `docs/conventions/types.md` §Core dichotomy ("The conversion lives next to the wire type"); the orphan rule allows ingestion to add these impls because ingestion owns the Entity even though Model is foreign (from shared).
  - The `StatisticValue` Model + `StatisticValueEntity` and `SourceChoice` Model + `SourceChoiceEntity` STAY in ingestion entirely. Consumer-side `statistic_value` reads happen against the SQLite shards (different column set: `region_iso3 text` not `region_id uuid`; no `superseded`; no FK references); the producer-side Postgres-shaped `StatisticValue` Model isn't the right consumer type. `SourceChoice` is producer-only merge configuration baked into shards at build time.
- **FR-005a**: System MUST move `NaiveDatePeriod` (struct + `from_year` constructor + `to_year` query) from `ingestion/src/adapter/adapter_model.rs` to `shared/src/canonical/canonical_model.rs`. It's a pure value type (half-open `[start, end)` interval of `NaiveDate`); currently lives under `adapter/` only because that's where the producer's normalization pipeline first uses it. Consumers need it for period-keyed SQLite shard queries (the year scrubber on the map view sets `(period_start, period_end)` and reads matching rows). Drop the `#[allow(dead_code)]` on `to_year` — it becomes consumer-side live code. The other `adapter_model.rs` types (`AdapterOptions`, `NormalizedStatisticValue`, `NormalizeOutcome`, `IngestWarning`, `IngestWarningKind`) stay in ingestion — they're producer-side normalization pipeline types consumers don't see.
- **FR-006**: System MUST migrate every ingestion-side reference to a moved type (`crate::canonical::canonical_model::StatisticKind`, `::Region`, etc.) to the corresponding `shared::canonical::canonical_model::*` path directly. Ingestion MUST NOT forward the moved types through a `pub use shared::...` re-export. Once the canonical Models leave, `ingestion/src/canonical/canonical_model.rs` (which then holds only the producer-side `*Entity` types, their conversion impls, and the producer-only Models) is renamed to reflect its content (proposed: `canonical_entity.rs`).
- **FR-007**: System MUST move `ingestion/src/artifact/writer/manifest.rs`'s manifest schema (the `ManifestSerializer<'a>` + `ManifestEntry<'a>` structs and the constants `MANIFEST_FILENAME`, `SUBDIR_GEOMETRY`, `SUBDIR_DATA`) to `shared/src/artifact/manifest.rs` as the canonical owned form (with `'static` strings instead of `&'a str`; ownership moves to the consumer side per `client.md` §Manifest schema). The producer-side `write_manifest` function in `ingestion/` stays in `ingestion/`; it now consumes the `shared::artifact::manifest::Manifest` shape rather than its private serializer struct. The serialize-side determinism property (BTreeMaps for stable key order; `serde_json::to_string_pretty`; byte-equal output on identical inputs) is preserved.
- **FR-008**: System MUST move the cross-cutting helpers from `ingestion/src/filesystem.rs` (the SHA-256 + file helpers — `sha256_hex(bytes)`, `sha256_hex_of_file(path)`, `filename_of(path)`, `read_bytes(path)`, `load_hashed_file(...)`, plus the types `FileReference` and `Hashed<T>`) wholesale to `shared/src/filesystem.rs`. Items gated off wasm32 (`FileReference`, `sha256_hex_of_file`, `filename_of`, `read_bytes`, `load_hashed_file`) use `#[cfg(not(target_arch = "wasm32"))]`; cross-target items (`sha256_hex`, `Hashed<T>`) work on both. The producer-side orchestrators in `ingestion/src/artifact/hashing.rs` (`hash_sqlite_shards`, `hash_geometry`) stay in ingestion and reach the helpers via `shared::filesystem::*`. `ingestion/src/filesystem.rs` is deleted and `pub mod filesystem;` removed from `ingestion/src/lib.rs`; ingestion call sites import `shared::filesystem` directly (no re-export).
- **FR-009**: System MUST add `verify_sha256(bytes: &[u8], expected_hex: &str) -> Result<(), AppError>` to `shared::filesystem`. Returns `Ok(())` on match; `Err(AppError)` on mismatch whose message contains both `expected_hex` (first 8 hex chars) and the actual hash (first 8 hex chars), per the §Edge Cases for `Bundle::open`. Cross-target so wasm32 consumers (the web client's loader) can call it.

#### Manifest consumer types

- **FR-010**: System MUST define `shared::artifact::manifest::Manifest` as the owned consumer-side type with these fields (matching the on-the-wire shape in `client.md` §Manifest schema, extended with the schema-version gate per the §Clarifications session): `manifest_schema_version: u32` (v1 emits `1`; `parse_manifest` rejects any other value), `version: String`, `artifact_created: chrono::DateTime<chrono::Utc>`, `geometry: ManifestEntry`, `statistics: BTreeMap<StatisticKind, BTreeMap<LicenseShardClass, ManifestEntry>>`, `source_revisions: BTreeMap<DataSourceKind, SourceRevision>`. ### Key Entities

- **`shared/` workspace member**: a new library crate at the workspace root that compiles for both the host (Apple Silicon Mac mini) and `wasm32-unknown-unknown` (web client). Owns the consumer-side types + parsers + loader for artifact bundles; the renderer + projection + hit-testing live in 006-core-renderer.
- **`shared::artifact::manifest::Manifest`**: the owned consumer-side parsed form of the on-the-wire manifest JSON. Replaces the producer's private `ManifestSerializer<'a>` struct as the canonical type; both ingestion (write side) and every client (read side) reach for it.
- **`shared::artifact::cache::ArtifactCache`**: the cross-platform async trait both `OpfsArtifactCache` (web) and `FileSystemArtifactCache.swift`-backed UniFFI wrapper (iOS) implement. The contract `Bundle::open` consumes by reference.
- **`shared::artifact::bundle::Bundle`**: pure parsed data — the parsed manifest + eagerly-parsed `FlatGeobufReader` (with its R-tree spatial index) + `BTreeMap<StatisticShardKey, Vec<u8>>` of raw shard bytes (filtered by `DistributionContext::authorized_classes` at open time) + the distribution context. `Send + Sync`. The value the renderer holds via `Arc<Bundle>` and hot-swaps via `tokio::sync::watch`. The renderer opens its own thread-local `rusqlite::Connection` against `bundle.shard_bytes` (in 006-core-renderer); `Bundle` itself holds no Connection.
- **`shared::artifact::discovery::DiscoveryDocument`**: the deserialized form of `https://eafora.org/discovery`. Validated to `schema_version == 1` at parse time.
- **`shared::license::DistributionContext`**: the enum that decides which license shards a particular client attaches at bundle-open time. Two variants in v1 (`FirstParty`, `Embedded`).
