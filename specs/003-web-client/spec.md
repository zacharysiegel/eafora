# Feature Specification: Web client (WASM + Leptos + wgpu shell + OPFS cache)

**Feature Branch**: `003-web-client`

**Created**: 2026-06-22

**Status**: Draft

**Input**: User description: "web client — WASM bundle, page shell, client-side map view rendering against static-asset embedded bundle, OPFS cache adapter. Scope per docs/architecture/client-web.md §Follow-up work: enough to surface the perf-budget report and render the static stub-equivalent of docs/design/stub-desktop.html against real data."

## Scenarios & Testing *(mandatory)*

### First-paint map render against the embedded bundle (P1)

A first-time visitor opens `https://eafora.org/` in a modern desktop browser (Chromium / Safari / Firefox). The page-shell HTML lands; the WASM bundle downloads; Leptos mounts on `<div id="leptos">`; the static-asset embedded bundle (shipped alongside the WASM on Cloudflare Workers Assets) loads and parses through `core::artifact::Bundle`; the map view renders the world's country polygons in a Miller cylindrical projection with the current TFR statistic painting the choropleth (red intensity scale). The choropleth legend, statistic picker, year scrubber, and source-panel chrome render in the layout established by `docs/design/stub-desktop.html`. The map is interactive: clicking a country selects it (1px red outline; the visual hit region is the unscaled polygon per the hover-scaling rule in `docs/architecture/overview.md` §Hover scaling); the statistic picker swaps the painted statistic; the year scrubber moves through time. This is the deliverable that closes the §Follow-up work item in `docs/architecture/client-web.md`. Without it, every other web-side feature stays speculative.

**Acceptance Scenarios**:

1. **Given** a first-time visitor on a modern desktop browser (Chromium 124+, Safari 18.4+, Firefox 130+) with no Eafora data in OPFS, **When** they navigate to `https://eafora.org/`, **Then** the page-shell HTML renders within 1 second, the WASM bundle finishes downloading + initializing, the static-asset embedded bundle loads, and the world map renders with country polygons and choropleth coloring for the default statistic (TFR) within the perf-budget target of 2 MB compressed at first paint.
2. **Given** the map has rendered against the embedded bundle, **When** the visitor clicks a country polygon, **Then** the country becomes the selected region (1px red outline), the top-left detail panel updates to show that country's name + the active statistic's value + the source attribution. Clicking another country swaps the selection; clicking the background deselects.
3. **Given** the map has rendered, **When** the visitor changes the statistic picker (e.g. selects a different demographic indicator the embedded bundle ships), **Then** the choropleth re-paints synchronously (no animation per `docs/design/README.md` §Animation v1 policy), reflecting the newly-active statistic.
4. **Given** the map has rendered with year scrubber at the most-recent year (the only year the embedded bundle ships per `docs/architecture/client.md` §Embedded downsampled artifact), **When** the visitor drags the scrubber to a year not in the embedded bundle, **Then** the bundle has no value for that year and the choropleth renders that country as "no data" (per the design vocabulary: white fill, no choropleth color); panning still works.
5. **Given** the WebGPU backend is available, **When** the visitor opens the page, **Then** the wgpu instance picks `Backend::WebGpu`; **When** they open it with `?renderer=webgl2`, **Then** the wgpu instance picks `Backend::Gl` and the visual output is identical (renderer is designed to the WebGL2 feature set per `client-web.md` §WebGPU vs WebGL2 fallback policy).
6. **Given** a browser that cannot initialize any wgpu adapter (no WebGPU, no WebGL2), **When** the visitor opens the page, **Then** a visible in-page message replaces the map area (plain HTML, styled per `docs/design/README.md` panel pattern); a console error logs the diagnostic detail; no fallback / no retry / no degraded mode.

### OPFS cache adapter persistence (P2)

The web client's `OpfsArtifactCache` (in `web/src/cache.rs`) implements the cross-platform `ArtifactCache` trait defined in `core::artifact`. Through this feature the cache adapter is exercised end-to-end against a real OPFS in headless Chrome (`wasm-bindgen-test --headless --chrome`): a `put` → `get` round-trip returns byte-equal bytes; a missing key returns `None`; `delete_version` removes a version subtree; `list_versions` enumerates persisted versions; the "keep the current version + the most recent prior version" eviction policy (per `client.md` §Cache eviction) removes older subtrees on startup; `navigator.storage.persist()` is requested on first launch; `navigator.storage.estimate()` is consulted before each `put` to fail fast on quota pressure. A `QuotaExceededError` surfaces as an `AppError` whose message starts with the literal `cache: quota exceeded`. A browser without OPFS support surfaces an `AppError` whose message starts with `cache: opfs unsupported`. The live CDN fetch flow (P3) is built on top of this adapter; this story establishes the cache contract as a self-contained, verifiable surface before the wider flow lands.

**Acceptance Scenarios**:

1. **Given** a headless-Chrome test environment with empty OPFS, **When** `cache.put("2026-06-22+ada", "manifest.json", &bytes)` runs followed by `cache.get("2026-06-22+ada", "manifest.json")`, **Then** the returned `Vec<u8>` is byte-equal to the input.
2. **Given** an empty cache, **When** `cache.get("2026-06-22+ada", "manifest.json")` runs, **Then** the result is `Ok(None)`.
3. **Given** OPFS holds three version subtrees (`2026-06-01+...`, `2026-06-10+...`, `2026-06-22+...`), **When** the cache initializes at startup, **Then** `evict_old_versions` deletes `2026-06-01+...` and leaves the two most recent subtrees intact (per `client.md` §Cache eviction "keep current + most-recent prior").
4. **Given** a browser context where `navigator.storage.estimate()` reports `quota - usage < bytes.len() + 4 MB`, **When** `cache.put(...)` runs, **Then** it returns an `AppError` whose `to_string()` starts with `cache: quota exceeded`; no partial write lands.
5. **Given** a browser without OPFS support (older Safari per `caniuse.com`), **When** the cache constructor runs, **Then** it returns an `AppError` whose `to_string()` starts with `cache: opfs unsupported`; the loader falls back to in-memory-only mode and the embedded bundle remains the floor (no crash, no blank page).

### Discovery + speculative parallel fetch + bundle hot-swap (P3)

When the producer side has stood up `https://repository.eafora.org/` and the `latest/manifest.json` upload step (per `docs/architecture/client.md` §Live bundle: stable pointer), the web client picks up the live bundle on first visit and on each subsequent launch. The startup sequence per `client.md` §Speculative parallel fetch at startup: the discovery fetch (`https://eafora.org/discovery`) and the speculative manifest fetch (`<baked_repository_base_url>/latest/manifest.json`) fire in parallel; the embedded bundle has already rendered the map; the fetcher persists verified bytes into OPFS as they verify against the manifest's SHA-256 hashes; when both resolve, the live `Arc<Bundle>` is published on the `tokio::sync::watch::Sender<Arc<Bundle>>` and the map re-renders against the live bundle on the next scheduled redraw. The visual transition is instant per `docs/design/README.md` §Animation. On a returning visit with a populated OPFS, the cached live bundle replaces the embedded bundle as the floor for first paint, and the latest-revision check happens in the background. Until the producer-side prerequisites land, the flow is exercised against a same-origin stub manifest + shards committed under `web/static/embedded_artifacts/` and a stub discovery document at `web/static/discovery`; switching to real `repository.eafora.org` is a configuration change, not a code change.

**Acceptance Scenarios**:

1. **Given** a populated `https://repository.eafora.org/` with a `latest/manifest.json` pointing at a version newer than what the embedded bundle ships, **When** a first-time visitor lands on `/`, **Then** the embedded bundle renders first, the discovery + manifest fetches resolve concurrently, the shards download (concurrency capped at 6 per `client.md` §Stage 3), each shard's SHA-256 is verified, the OPFS cache writes through as bytes verify, and the renderer hot-swaps to the live bundle within a few seconds of first paint.
2. **Given** a returning visitor whose OPFS holds a live bundle from a prior visit and the producer has not published since, **When** they land on `/`, **Then** the cached live bundle renders as the first paint (skipping the embedded bundle as the starting point per `client.md` §Returning-visitor flow); the discovery + latest-manifest fetches still fire; the cached bundle is already current, so no re-download happens.
3. **Given** the discovery fetch fails (offline / 5xx / malformed document) but the speculative manifest fetch succeeds against the baked-in `repository_base_url`, **When** the client reconciles, **Then** the speculative result is used (per `client.md` §Speculative parallel fetch step 4) and the bundle hot-swaps normally; one round trip total.
4. **Given** the discovery fetch reports a `repository_base_url` different from the baked-in fallback (re-platform happened), **When** the client reconciles, **Then** the speculative-fetch result is discarded and a new manifest fetch fires against the discovered URL; the bundle hot-swaps once the new fetch resolves; two round trips total, one wasted.
5. **Given** a shard's SHA-256 does not match the manifest's recorded hash, **When** the fetcher verifies, **Then** the fetch retries once after approx. 100 ms; persistent mismatch surfaces a UI banner ("data unavailable, please reload"); the embedded bundle (or cached live bundle on returning visit) remains rendered as the floor.

### Perf-budget report (P4)

`scripts/measure-site-budget.sh` runs `cargo leptos build --release` and emits a labeled, narrow-terminal-safe report of the deployed asset sizes (per `docs/architecture/client-web.md` §Perf-budget warning). The report breaks first-paint and second-paint totals into their constituent pieces (WASM, JS shim, CSS, HTML, embedded artifacts; live geometry + statistic shards for second paint), compares each total against the 2 MB / 3 MB caps from `docs/architecture/client.md` §Web first-paint perf budget, and prints a "near cap" warning when a total exceeds approx. 90% of its cap. The script always exits zero — the warning is in the text output, never in the exit code (the cap is a target, not a contract). CI invokes the script on every PR and posts the output as a PR comment so regressions surface for human review.

**Acceptance Scenarios**:

1. **Given** a successful release build, **When** `scripts/measure-site-budget.sh` runs from the repo root, **Then** it prints a two-section report (first paint, second paint) with byte counts for each constituent and percentages against the cap; the script exits with status 0.
2. **Given** a release build whose first-paint total exceeds 90% of the 2 MB cap, **When** the script runs, **Then** the first-paint section's totals line ends with the literal `near cap` (per the example in `client-web.md` §Perf-budget warning).
3. **Given** a release build whose first-paint total exceeds the 2 MB cap, **When** the script runs, **Then** the totals line indicates the overage; the script still exits 0; CI surfaces the report to reviewers via PR comment but does not fail the build.
4. **Given** a PR that adds approx. 200 KB to the WASM bundle (e.g. a new dependency), **When** CI runs, **Then** the PR comment from the previous build (baseline) and the comment from this build (post-change) make the delta visible to reviewers without manual computation.

### Edge Cases

- **Cold-start with a slow connection** — the WASM bundle and the embedded artifacts download in parallel; the page shell renders text-only until the WASM finishes initializing; first paint of the map happens only after the embedded artifacts are parsed. A loading state covers the map area until then (plain CSS panel, no spinner per `docs/design/README.md` §Interaction).
- **Cached WASM, fresh embedded artifacts** — the WASM is HTTP-cached aggressively (Cloudflare Workers Assets handles via content-hashed filename), the embedded artifacts are not content-hashed and are HTTP-cached by Cloudflare's defaults. The visit hits cached WASM + freshly-fetched embedded artifacts; first paint is fast (~hundreds of milliseconds).
- **OPFS unavailable mid-session** (user clears site data via browser settings while the page is open) — the in-memory `Arc<Bundle>` keeps the map rendering; the next attempted `cache.put` returns `cache: quota exceeded` or `cache: opfs unsupported`; the loader surfaces the in-memory-only fallback message in the UI panel.
- **WebGPU initialization succeeds but a draw call panics** — `panic = "abort"` workspace-wide (per `docs/architecture/overview.md` §Workspace Cargo profile) kills the WASM module cleanly; the browser tab is left with the static page-shell HTML and the canvas frozen at the last frame; the user reloads to recover.
- **Cross-origin embedding via `<iframe src="https://eafora.org/">`** — works without cross-origin isolation headers (no `Cross-Origin-Opener-Policy`, no `Cross-Origin-Embedder-Policy`) because the client deliberately doesn't use `SharedArrayBuffer` (per `docs/architecture/overview.md` §Web client). A third-party site embedding the page sees the same map; only the `Embedded` distribution context's authorized license shards attach, but v1 only ships `base` so there is no functional difference yet.
- **Browser zoom (`Cmd-+`) at any level** — the page chrome scales proportionally; the map canvas remains pixel-stable (the wgpu surface tracks `canvas.clientWidth` / `canvas.clientHeight` × `devicePixelRatio`); choropleth legend's mono numerals stay tabular-aligned.
- **User browser-font-size override** — `rem`-anchored spacing and font sizes scale with the override; `px`-anchored borders (1px) and radii (≤1px) stay device-pixel-precise per `client-web.md` §Design tokens.
- **JavaScript disabled** — the page shell HTML loads but the Leptos `App` never mounts; the canvas stays blank; this is the documented unsupported configuration. Search-engine-indexable content (region detail and About pages, if they ship) would land in SSG'd HTML; their out-of-scope status for this feature means JavaScript-disabled visitors see only the empty shell. No mitigation in v1 (the map IS the product; there is no non-WASM rendering path).
- **CDN serves a stale `latest/manifest.json`** (Cloudflare edge cache hasn't refreshed yet) — the client uses the stale manifest, which references shards that still exist on R2 (immutable, content-hashed); the user sees a slightly older bundle until the next launch picks up the refreshed manifest. No correctness impact.

## Requirements *(mandatory)*

### Functional Requirements

#### Workspace + build toolchain

- **FR-001**: System MUST add a `web/` Cargo workspace member structured per `docs/architecture/client-web.md` §Workspace placement: `Cargo.toml` (depends on `core/`, `leptos`, `leptos_i18n`, `leptos_i18n_build`, `wasm-bindgen`, `wasm-bindgen-futures`, `web-sys`, `js-sys`, `gloo-net`, `log`, `console_log`, `console_error_panic_hook`); `style/` (plain CSS files); `static/` (verbatim-served assets including `embedded_artifacts/` and `discovery`); `src/` (feature-organized modules; `mod.rs` files only declare + re-export per the `mod.rs holds only declarations` rule).
- **FR-002**: System MUST configure `[package.metadata.leptos]` in `web/Cargo.toml` for the cargo-leptos pipeline per `client-web.md` §`cargo-leptos`: `bin-features = ["ssr"]`, `lib-features = ["hydrate"]`, `style-file = "style/main.css"`, `assets-dir = "static"`, `lib-profile-release = "wasm-release"`. The exact key spellings MUST be verified against the cargo-leptos version pinned in the workspace (see Assumptions).
- **FR-003**: System MUST define a `[profile.wasm-release]` profile in the workspace root `Cargo.toml` with `inherits = "release"`, `opt-level = "z"`, `lto = true`, `codegen-units = 1`, `strip = true`. Release builds MUST also invoke `wasm-opt -O4` via cargo-leptos's `wasm-opt-args` setting.
- **FR-004**: System MUST provide `scripts/sync-embedded-bundle.sh ./web/static/embedded_artifacts/` per `client-web.md` §Build dependency direction. The script verifies `$EAFORA_DOWNSAMPLED_DIR/latest/` exists (defaulting `EAFORA_DOWNSAMPLED_DIR` to `<repo-root>/data/downsampled/`), invokes `ingestion build --downsampled` first if not, then plain-copies the contents with `cp -R` into the destination. Plain copy only — no symlink, no hardlink, no `rsync`. `web/static/embedded_artifacts/` MUST be gitignored.
- **FR-005**: System MUST provide `scripts/precompress-site.sh` per `client-web.md` §Compression. The script iterates `target/site/`, runs `brotli -q 11 --keep` on each eligible file (`.wasm`, `.js`, `.css`, `.html`, `.json`, `.fgb`, `.sqlite`), skips already-compressed types (`.png`, `.jpg`, `.woff2`), and exits non-zero on failure. Invoked as the final step of `cargo leptos build --release`.
- **FR-006**: System MUST provide `scripts/measure-site-budget.sh` per `client-web.md` §Perf-budget warning. The script runs `cargo leptos build --release`; sums brotli-q11 sizes for first paint (WASM + JS shim + CSS + page-shell HTML + every file under `target/site/embedded_artifacts/`) and second paint (additionally summing each artifact file the live-bundle fetch will need on first online connection: geometry shard + every base statistic shard); prints a labeled key:value report with totals against the 2 MB / 3 MB caps; appends ` near cap` to totals lines that exceed approx. 90% of their cap; ALWAYS exits zero.

#### Page shell + Leptos app

- **FR-007**: System MUST provide a page-shell `index.html` template that cargo-leptos uses as the SSR shell. The shell MUST mount the Leptos `App` on `<div id="leptos">` (NOT on `<body>` directly, per `client-web.md` §Client-side map view). The `<head>` MUST set the viewport meta tag and link the bundled stylesheet at `/pkg/eafora.css`; other `<head>` entries (font preloads, OG tags, `<link rel="canonical">`) are open per `client-web.md` §Decisions still open.
- **FR-008**: System MUST define a `lib.rs` declaring submodules and a `#[wasm_bindgen(start)] fn hydrate()` that mounts the Leptos `App` for the client-side build per `client-web.md` §Workspace placement. The SSR-build entrypoint (`main.rs`) MUST exist and call `static_routes.generate(&leptos_options).await` then exit, even if no SSG routes are yet declared (i.e. the binary is a no-op pass-through at this point).
- **FR-009**: System MUST define `app.rs` containing the root `App` component with a `<Routes>` tree. v1 declares at minimum the `/` (map view) route. SSG-rendered region-detail and About-page routes are OUT of scope for this feature (see §Scope cutoff below); their addition is a follow-up feature.
- **FR-010**: System MUST localize every user-facing string via `leptos_i18n` per `client-web.md` §Localization scaffolding. English locale ships in `web/locales/en.json`; the discipline is "no bare string literal in a user-facing position" — `view! { <p>{t!(i18n, key)}</p> }` everywhere; never `view! { <p>"raw text"</p> }` for user-visible content. Bare strings remain acceptable for log messages, debug output, and internal identifiers.
- **FR-010a**: System MUST configure `leptos_i18n` via the build-script integration per `client-web.md` §Localization scaffolding §Integration: `web/Cargo.toml` lists `leptos_i18n` (runtime dep) + `leptos_i18n_build` (build dep); `web/build.rs` runs `Config::new("en")` → `TranslationsInfos::parse` → `generate_i18n_module(OUT_DIR/i18n)`; `web/src/lib.rs` brings the generated module into scope at the crate root via `include!(concat!(env!("OUT_DIR"), "/i18n/mod.rs")); use i18n::*;`; `app.rs` wraps the App root in `<I18nContextProvider>`.

#### Map view

- **FR-011**: System MUST implement the `MapView` component per `client-web.md` §Client-side map view. The component owns a `<canvas>` element (`map::canvas::MapCanvas`), the choropleth legend overlay (`map::legend::Legend`), and the control surfaces (statistic picker, year scrubber, source panel — `map::controls::Controls`). Layout matches `docs/design/stub-desktop.html` (top-left detail panel, top-right ranking table, bottom time scrubber, full continent choropleth).
- **FR-012**: System MUST bridge `<canvas>` to `wgpu::Surface` via `web/src/canvas_surface.rs::create_surface_from_canvas(canvas) -> Result<core::map::WgpuSurface, AppError>` per `client-web.md` §Rendering: wgpu surface acquisition. The function constructs a `wgpu::Instance` with backends `BROWSER_WEBGPU | GL`, creates the surface, requests an adapter (WebGPU primary, WebGL2 fallback via wgpu's downlevel backend), and returns the platform-agnostic surface to `core::map::map_renderer::Renderer::new(...)`. The exact wgpu API names MUST be verified against the version pinned in `core/`'s Cargo.toml (see Assumptions).
- **FR-013**: System MUST drive rendering event-driven per `client-web.md` §Client-side map view: a dirty flag plus `requestAnimationFrame`. Input handlers (`pointerdown` / `pointermove` / `wheel` / statistic-picker selection / year-scrubber drag) and bundle-channel `Receiver::changed()` notifications set the dirty flag and call a `request_redraw()` that schedules `requestAnimationFrame(draw)` if a frame isn't already pending. Multiple `request_redraw()` calls between vsyncs coalesce into one draw. There MUST NOT be a persistent rAF loop at the display's refresh rate while idle.
- **FR-014**: System MUST honor `docs/design/README.md` §Animation through v1: state changes are instant; no animation curves on selection / hover / statistic-swap / year-scrub. Future v2+ animations are governed by the crispness-over-smoothness rule documented in the design doc.
- **FR-015**: System MUST surface a `?renderer=webgl2` query-string flag per `client-web.md` §WebGPU vs WebGL2 fallback policy: when present, `canvas_surface.rs` forces `Backend::Gl` before the wgpu instance is constructed (for developer parity testing). Not a user-facing toggle.
- **FR-016**: System MUST handle adapter-request failure (no WebGPU and no WebGL2) per `client-web.md` §WebGPU vs WebGL2 fallback policy: log a `log::error!` carrying the failure detail (backends attempted, adapter-request result); replace the map area with a visible in-page message (plain HTML rendered by Leptos, styled per `docs/design/README.md` panel pattern) stating the browser doesn't support the rendering backends Eafora requires, with a link to the About page (when /about lands). No fallback, no retry, no degraded mode.

#### OPFS cache adapter

- **FR-017**: System MUST implement `OpfsArtifactCache` in `web/src/cache.rs` satisfying the cross-platform `ArtifactCache` trait defined in `core::artifact` per `client.md` §Cache eviction. Required functions: `put(version_label, file_relative_path, bytes) -> Result<(), AppError>`, `get(version_label, file_relative_path) -> Result<Option<Vec<u8>>, AppError>`, `list_versions() -> Result<Vec<String>, AppError>`, `delete_version(version_label) -> Result<(), AppError>`.
- **FR-018**: System MUST be a zero-sized type that resolves `navigator.storage.getDirectory()` on every call per `client-web.md` §Threading model: "The `OpfsArtifactCache` deliberately does **not** appear in [the thread_local list]. It is a zero-sized type holding no state". No cached `FileSystemDirectoryHandle`. No `thread_local!`, no `RefCell`.
- **FR-019**: System MUST store files at `<opfs-root>/artifacts/<version_label>/<file_relative_path>` per `client-web.md` §Directory layout in OPFS. The directory shape mirrors the CDN's per-version layout one-to-one: `cache.get(version, "<relative_path>")` resolves to `<opfs-root>/artifacts/<version>/<relative_path>` regardless of how the producer organizes subdirectories.
- **FR-020**: System MUST call `navigator.storage.persist()` on first launch per `client-web.md` §Quota and persistence step 1. The result (`true` = persistent; `false` = best-effort) is logged via `log::info!` but does NOT block cache initialization.
- **FR-021**: System MUST call `navigator.storage.estimate()` before each `put` and verify `quota - usage >= bytes.len() + 4_194_304` (the 4 MB safety margin per `client-web.md` §Quota and persistence step 2). On failure, the `put` returns an `AppError` whose message starts with the literal `cache: quota exceeded`.
- **FR-022**: System MUST translate any `QuotaExceededError` raised by `createWritable()` / `write()` to the same `cache: quota exceeded`-prefixed `AppError` per `client-web.md` §Quota and persistence step 3.
- **FR-023**: System MUST detect OPFS unavailability (older Safari per `caniuse.com`) at cache constructor time and return an `AppError` whose message starts with `cache: opfs unsupported` per `client-web.md` §Quota and persistence step 5. The loader then runs in in-memory-only mode; the map still renders from the static-asset embedded bundle.
- **FR-024**: System MUST implement `OpfsArtifactCache::evict_old_versions` per `client-web.md` §Directory layout in OPFS, called at startup after the cache opens. It enumerates version subtrees, picks the two most recent by `<version_label>` lexicographic order (the `YYYY-MM-DD+<surname>` shape sorts correctly), and deletes the rest.

#### Browser fetch adapter

- **FR-025**: System MUST implement `web/src/fetch.rs` per `client-web.md` §Browser fetch adapter. Surface: `pub async fn fetch_manifest(repository_base_url: &str) -> Result<Vec<u8>, AppError>` and `pub async fn fetch_artifact_file(repository_base_url: &str, version_label: &str, relative_path: &str) -> Result<Vec<u8>, AppError>`. Both delegate to the browser's `fetch()` via `web_sys::window().unwrap().fetch_with_str(url)` + `wasm_bindgen_futures::JsFuture`.
- **FR-026**: System MUST pass parallelism cap 6 from the web shell to `core::artifact`'s loader semaphore per `client.md` §Stage 3 + `client-web.md` §Browser fetch adapter.
- **FR-027**: System MUST resolve `repository_base_url` at runtime via the discovery URL flow per `client.md` §Discovery and live bundle resolution: the client fetches `https://eafora.org/discovery`, reads `repository_base_url` from the response, and uses that for every shard fetch. A baked-in fallback (populated at build time by a small script that reads the current discovery doc) handles the case where discovery itself fails.
- **FR-028**: System MUST implement the speculative parallel fetch at startup per `client.md` §Speculative parallel fetch at startup: discovery fetch + manifest fetch against the baked-in URL fire in parallel; reconciliation per the decision-tree in that section. Speculative-fetch errors are silenced ONLY while discovery is still in flight; once the authoritative URL is known, errors surface normally.
- **FR-029**: System MUST write verified bytes to the OPFS cache as they verify against the manifest's SHA-256 entries — no waiting on discovery to complete per `client.md` §Speculative parallel fetch at startup. The cache is keyed by `version_label`; bytes that match a manifest's hashes are correct bytes for that version regardless of which URL served them.

#### Bundle hot-swap

- **FR-030**: System MUST publish the live `Arc<Bundle>` on a `tokio::sync::watch::Sender<Arc<Bundle>>` once the live fetch completes per `client.md` §Bundle hot-swap. The renderer's `tokio::sync::watch::Receiver<Arc<Bundle>>` (wrapped in a `RefCell` in a `thread_local!` per `client-web.md` §Threading model) `await`s `Receiver::changed()` and schedules a redraw on each wake; the next draw reads the new `Arc<Bundle>` via `Receiver::borrow()` and renders against it.
- **FR-031**: System MUST hold `core::map::map_renderer::Renderer` in a `thread_local! { static RENDERER: RefCell<Renderer> = ...; }` per `client-web.md` §Threading model (the renderer has `&mut self` methods that update frame state). The `tokio::sync::watch::Sender<Arc<Bundle>>` is held in a `thread_local!` as a bare `Sender` (NOT wrapped in `RefCell` — `Sender::send` takes `&self`).

#### Deploy target

- **FR-032**: System MUST configure `wrangler.toml` for Cloudflare Workers Assets per `client-web.md` §`wrangler.toml`: `name = "eafora-web"`, a `compatibility_date`, and `[assets] directory = "../target/site"`. NO `main` field, NO Worker script — pure static asset serving. The deploy command is `wrangler deploy`.
- **FR-033**: System MUST commit `web/static/_headers` per `client-web.md` §Headers, specifying response headers per path pattern. Rules and their rationale live in a comment block at the top of `web/static/_headers` itself, not in this spec. At minimum: `Content-Type: application/json` for `/discovery`; `Cache-Control: public, max-age=3600` for `/discovery`; `Cache-Control: public, max-age=31536000, immutable` for content-hashed assets (WASM bundle filename includes a hash via wasm-bindgen).
- **FR-034**: System MUST commit `web/static/discovery` (a plain JSON file) following the schema in `client.md` §Discovery document shape: `schema_version: 1`, `repository_base_url: "https://repository.eafora.org"`, `minimum_client_version: "0.1.0"`, `sunset: null`. The file ships at `https://eafora.org/discovery`. Updating it is a normal commit + redeploy.

#### Visual identity + CSS

- **FR-035**: System MUST organize CSS under `web/style/` per `client-web.md` §CSS architecture: `main.css` entrypoint @imports the rest in dependency order (tokens → reset → typography → layout → page-specific); per-feature stylesheets (`map.css`, `region.css`, `about.css`); component partials under `components/` (`panel.css`, `button.css`, ...).
- **FR-036**: System MUST commit `web/style/tokens.css` as the single source of truth for color / spacing / type scale / border weight per `client-web.md` §Design tokens. Tokens MUST match the values in `client-web.md` §Design tokens (`--color-paper: #ffffff`, `--color-ink: #000000`, `--color-accent-active: #d50000`, `--color-accent-link: #0050ff`, `--color-rule: #d4d4d4`; T-shirt spacing scale xs / sm / md / lg; sans + mono families; body / data type sizes and line heights; 1px borders; 0 / 1px radii). Every other CSS file references tokens via `var(--token-name)`; raw color values appear nowhere else.
- **FR-037**: System MUST set `font-variant-numeric: tabular-nums` on every numeric display per `docs/design/README.md` §Typography. Enforced via a `.numeric` CSS class applied to every element rendering a number; the class is defined in `web/style/typography.css`.
- **FR-038**: System MUST provide a `max-width: 768px` media query breakpoint per `client-web.md` §Responsive design: below this width, layout switches to the single-column mobile pattern; above, the desktop pattern applies. Bespoke mobile UX work (touch tuning, mobile-only gestures, mobile-perf optimization) is OUT of scope per `docs/architecture/overview.md` §Web client; the mobile layout is best-effort only.
- **FR-039**: System MUST NOT introduce Tailwind or any utility-class library per the project's `feedback_no_tailwind` memory.

#### Testing

- **FR-040**: System MUST cover the OPFS cache adapter contract via `wasm-bindgen-test --headless --chrome` per `client-web.md` §Testing strategy: `put` → `get` round-trip (byte-equal); `get` on missing key returns `None`; `evict_old_versions` removes the right subtrees; `cache: quota exceeded`-prefixed `AppError` on quota failure; `cache: opfs unsupported`-prefixed `AppError` on missing OPFS.
- **FR-041**: System MUST cover the browser fetch adapter's error mapping in headless Chrome: simulated 4xx / 5xx responses map to `AppError`s carrying the source URL and HTTP status in the message body. The simulation mechanism (mock server, `web_sys` interception layer, fetch override) is a plan-level decision.
- **FR-042**: System MUST cover `canvas_surface.rs` in headless Chrome: the surface's reported size matches the canvas's `clientWidth` / `clientHeight`; resize events propagate to the surface; `?renderer=webgl2` forces `wgpu::Adapter::backend() == Backend::Gl`; the unflagged path picks `Backend::WebGpu` on browsers that support it.
- **FR-043**: System MUST NOT include end-to-end browser tests per `client-web.md` §Testing strategy. Visual ground truth lives in `docs/design/stub-desktop.html`; parity is checked manually before every deploy.

### Key Entities

- **`OpfsArtifactCache`**: the web-platform concrete implementation of the `ArtifactCache` trait. Zero-sized type; stateless; resolves `navigator.storage.getDirectory()` per call. Lives at `web/src/cache.rs`.
- **`WgpuSurface`** (platform-agnostic wrapper): the `wgpu::Surface` plus the adapter / device / queue triple that the renderer holds across draws. Constructed once per session via `canvas_surface::create_surface_from_canvas`. Lives in `core::map`.
- **`Renderer`** (held in a `thread_local! { static RENDERER: RefCell<Renderer> = ...; }`): owns the `WgpuSurface`, the `tokio::sync::watch::Receiver<Arc<Bundle>>`, and the dirty flag. Lives in `core::map::map_renderer`.
- **`Bundle`** (re-used from `core::artifact`): the parsed manifest + the open SQLite shard databases + the parsed FlatGeobuf reader. Published via `tokio::sync::watch::Sender<Arc<Bundle>>` and hot-swapped on every successful live-bundle load.
- **`DiscoveryDocument`** (in `core::artifact` or `web/src/fetch.rs`): the deserialized form of the JSON at `https://eafora.org/discovery`. Fields per `client.md` §Discovery document shape: `schema_version: u32`, `repository_base_url: String`, `minimum_client_version: String`, `sunset: Option<String>`.
- **Embedded artifact bundle** (the bytes under `web/static/embedded_artifacts/`): the producer's downsampled output, copied verbatim into the web crate's static-asset tree at build time. Loaded via the browser's fetch path (no special-case for static origin) and parsed by `core::artifact::Bundle::open(...)`. NOT under version control; rebuilt on every CI build.

## Assumptions

- The producer-side `ingestion build --downsampled <output-dir>` exists. The first producer follow-up listed in `client.md` ("Add `ingestion build --downsampled` for generating the native-client embedded bundle") is the producer-side dependency; `scripts/sync-embedded-bundle.sh` invokes it.
- The producer side has NOT necessarily stood up `repository.eafora.org` or the `latest/manifest.json` upload step at the moment this feature's PR opens. Until those land, the live-fetch path (P3) is exercised against a stub manifest + shards committed under `web/static/embedded_artifacts/` and a stub discovery document at `web/static/discovery` whose `repository_base_url` points at the same origin (`https://eafora.org/embedded_artifacts/` or equivalent). Switching to the real `repository.eafora.org` is a one-commit edit to the discovery document, not a code change.
- Leptos 0.8.x and cargo-leptos 0.3.x are the pinned versions; the `[package.metadata.leptos]` keys named in FR-002 are valid for those versions. If a newer pin is adopted before this feature lands, FR-002's keys MUST be re-verified against the new version's documentation (per `client-web.md` §Things to verify #1).
- The wgpu surface-from-canvas API (`Instance::create_surface_unsafe` with `SurfaceTargetUnsafe::Canvas` per `client-web.md` §Rendering: wgpu surface acquisition) is current as of the wgpu version pinned in `core/`'s Cargo.toml. If the API name has shifted, `canvas_surface.rs` adapts accordingly (per `client-web.md` §Things to verify #2).
- `leptos_i18n` is at version 0.6.2 (April 2026, compatible with Leptos 0.8.x). The build-script-driven integration described in FR-010a matches this version's documented setup.
- The Safari OPFS support cutoff is captured by the `cache: opfs unsupported` AppError prefix; the exact iOS / macOS Safari version cutoff is to be verified against `caniuse.com` before relying on the §Quota and persistence step 5 fallback path (per `client-web.md` §Things to verify #4).
- The Cloudflare Workers Assets routing to `eafora.org` (apex domain) is configured in the Cloudflare dashboard outside the codebase. The `wrangler.toml` adds the asset bundle; the dashboard pairs it with the domain.

Staleness of the embedded bundle is not a correctness concern because the live CDN fetch upgrades it on first online interaction per `client.md` §Discovery and live bundle resolution.

## Scope cutoff

This feature lands the WASM bundle + page shell + map view (`/`) + OPFS cache adapter + perf-budget report — the §Follow-up work bullet from `docs/architecture/client-web.md` verbatim. Adjacent surfaces that ARE in the cross-cutting architecture but ARE NOT in this feature:

- **SSG `/region/<region.code>` and `/about` routes.** Documented in `client-web.md` §Routing and SSG; will land as a follow-up feature. The Leptos `App`'s `<Routes>` tree in this feature declares only `/`. The SSR-build entrypoint (`main.rs`) is in place as a no-op pass-through so the build pipeline is ready; adding routes is one Rust change per route in the follow-up.
- **Live CDN fetch wired against the real `repository.eafora.org`.** The discovery + live-fetch + hot-swap flow (P3) is implemented and exercised against a same-origin stub. Pointing the discovery document at the real CDN is a one-commit edit deferred until the producer-side prerequisites land (per `client-web.md` §Follow-up work bullet 2). Both can land in any order before the first production deploy.
- **Worker-based SQLite engine** backed by OPFS `FileSystemSyncAccessHandle`. Per `client.md` §SQLite in the client, the migration trigger is "any per-statistic shard grows past approx. 30 MB"; through v1 the single-threaded shape is intentional. Tracked in `docs/backlog.md` §Client.
- **Centralized design tokens with codegen to per-platform files.** Per `docs/backlog.md` §Client, this is a v1.5+ concern; v1's token set is small enough (handful of colors, 4-step spacing scale, 2 fonts) that hand-syncing across platforms is cheap.
- **Region index view** (the v1.5 non-map browse surface). Per `docs/backlog.md` §Client.

## Constitution Check

Per Constitution §Compliance review, this spec honors the binding principles as follows:

- **Principle I (Educational neutrality)**: directly served. The web shell's UI text is limited to labels, units, source attribution, and statistic definitions; no editorial copy. The About-page editorial framing is OUT of scope for this feature (see §Scope cutoff); when it lands, the design vocabulary it inherits from `docs/design/README.md` §Naming and the About page keeps the framing factual.
- **Principle II (Source provenance — NON-NEGOTIABLE)**: applies. The source-panel chrome in the map view exposes the `source_revisions` block from `manifest.json` per `docs/architecture/client.md` §Manifest schema (consumer view); every datum the user sees in a detail panel reads through `core::*` queries against the bundle's SQLite shards, each of which carries its source via the producer-side merge step's `data_source_id` lineage.
- **Principle III (Rust core, native UI shells)**: directly served. The web shell is Leptos (with the WASM compilation produced by `cargo-leptos`); the Rust core (`core/`) handles manifest parsing, SQLite queries, FlatGeobuf reading, hit-testing, projection math, and the wgpu rendering pipeline. The web crate is thin platform glue per the "1–2k LOC per-platform layer" target in `client.md` §Cross-platform consistency.
- **Principle IV (Singularity convention parity)**: applies. The web crate uses pre-locked dependencies (Leptos, wasm-bindgen, web-sys, gloo-net, leptos_i18n) and the project's locked Rust-stack picks (log + env_logger-style logging, dotenvy is N/A in the browser, AppError shaped through `minimer`-via-`core`). New web-side dependencies (e.g. `console_error_panic_hook`, `console_log`) are scoped to the browser environment and don't affect Singularity's pattern; they're discussed with the owner at plan time if questions arise. Wildcard re-exports per `feedback_wildcard_re_exports`.
- **Principle V (Explicit over implicit)**: applies. The web crate doesn't host HTTP routes (no actix-web); the Browser fetch adapter calls `web_sys::window().unwrap().fetch_with_str(url)` directly through `wasm_bindgen_futures::JsFuture` (the wire is visible at the call site). No RPC framework, no Leptos `#[server]`, no tRPC-style codegen. `leptos_i18n` is a build-time codegen for translation accessors, not a network abstraction; it's the established convention for Leptos i18n and was vetted as a "library convention" per `feedback_eafora_library_conventions`. Imperative routing in `app.rs` (a manual `<Routes>` tree); no route attribute macros.
- **Principle VI (CDN-delivered data, no live API through v2)**: directly served. The web client consumes only the manifest + shards served from the static CDN (`repository.eafora.org`) and the static discovery document at `eafora.org/discovery`. No origin-server calls; no live API; no v3+ surface. The Cloudflare Workers Assets deploy is purely static (no Worker handler per FR-032).
- **Principle VII (Test-first for core logic)**: applies to the web-side helpers per `client-web.md` §Testing strategy. OPFS cache adapter contract, browser fetch error mapping, and canvas-to-wgpu bridge each have headless-Chrome unit tests under `wasm-bindgen-test`. The Leptos UI components themselves (per Constitution VII's exception clause for UI shell code) are exempt from strict TDD; visual ground truth lives in `docs/design/stub-desktop.html` and parity is checked manually pre-deploy.
- **Principle VIII (Workflow discipline)**: this is the third `/speckit-specify` feature; spec / plan / tasks land in the same PR per `feedback_spec_and_plan_same_pr.md`. Branch `003-web-client` follows the per-body-of-work + `>>> branch:` marker convention.

No principle violations identified; no constitution amendments proposed.
