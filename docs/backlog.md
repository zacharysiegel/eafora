# Backlog

Deferred work items captured for future pickup. Each entry: what, why deferred, what triggers picking it up.

This file is **not** a roadmap — items here have no committed timeline and no priority order. The roadmap and current sequencing live in `docs/product/product-plan.md`, per-feature spec docs under `specs/`, and the active branch list. Items move out of this file when they enter active work (become a spec, a branch, or an inline plan in a relevant architecture doc).

## Ingestion / producer

- **Decouple geometry from per-version artifact bundles.** The current shape re-uploads the full geometry file under every published `version_label`. Geometry changes rarely (Natural Earth boundary updates are infrequent; subnational additions happen in discrete v2+ steps), so re-publishing it every version wastes R2 storage and bandwidth. A future shape publishes geometry to its own content-addressed key shared across versions, with the per-version manifest referencing it by URL (absolute, or rooted somewhere other than the version directory). Affects the publish flow and the manifest's `relative_path` resolution rule; invisible to consumers as long as they resolve URLs from the manifest entry rather than string-formatting paths. **Trigger:** R2 storage cost or upload time becomes a real signal. See `docs/architecture/ingestion.md` and `docs/architecture/client.md` §Decisions still open for related design notes.

## Client

- **Region index view (v1.5).** A non-map browse surface: list every region in the dataset and let the reader sort by statistic, search by name, optionally drill through region → subregion → country in a collapsible tree. Complements the map (the headline surface), not replaces it. Same visual vocabulary as the rest of the app per `docs/design/README.md` §Future surfaces. Reachable from the top nav; URL shape (`/index` vs `/regions` vs other) decided when the spec lands. Sub-decisions deferred: flat sortable list vs. tree vs. both with a toggle; whether the search is fuzzy or exact-prefix; whether the sort dimension persists across visits. It is also the only keyboard and assistive-technology path to choosing a region, which is a stronger reason than browsing convenience: selecting a region today means a pointer hit-test against the map canvas, so a keyboard-only reader can open the detail surface (the expand control is the first tab stop) but only ever onto the world figure. Two smaller pieces of the same gap, worth doing whenever this is picked up: returning focus to the expand control when the dock collapses, since the control that opened it no longer exists by then, and giving the map itself a keyboard affordance if the index does not turn out to be enough. **Trigger:** v1 has shipped and the index is the next user-facing surface. May earn earlier escalation if a TestFlight tester or web user explicitly asks for "show me every country" before v1 closes, or if keyboard access becomes a stated requirement.
- **Move web SQLite engine into a dedicated Worker, backed by OPFS `FileSystemSyncAccessHandle`.** v1 ships SQLite in the main-thread WASM with shards held as `Vec<u8>` in linear memory — fine because per-statistic shards stay in the tens-of-KB-to-low-MB range through v2. When shards grow past the single-threaded-friendly size, the SQLite engine needs to move to a Worker so it can use `FileSystemSyncAccessHandle` (Worker-only API) for streaming page reads against an OPFS-backed file, rather than fully resident in memory. New work: separate WASM bundle containing only the SQLite engine + a thin RPC layer; main-thread query API turns into `postMessage` round-trips; OPFS write-through on cache update. See `docs/architecture/client-web.md` §Worker migration path for the structural shape. **Trigger:** any per-statistic shard grows past approx. 30 MB. Likely lit up by v2's license-shards landing or subnational statistics arriving.
- **Watcher for `core/` changes that auto-rebuilds the iOS xcframework and reloads the app in the simulator.** Today the iOS dev loop is: edit Rust → manually re-run the xcframework build script → manually rebuild and relaunch the app. A `cargo watch` or `fswatch` invocation that triggers `scripts/build-ios-xcframework.sh` on `core/` changes, then `xcodebuild build && xcrun simctl install booted ./Eafora.app && xcrun simctl launch booted org.eafora.Eafora` automatically, would close the loop end-to-end. Note: this is fast-rebuild-and-relaunch, not true hot reload — Apple doesn't permit native code-replacement in a running app on iOS, so the running process exits and a fresh one starts each cycle. App state is lost per cycle; the cached bundle and OPFS-equivalent file-system data persist. Realistic latency is a few seconds per Rust change; acceptable for tightening the loop. **Trigger:** the iOS dev loop becomes a real friction point — likely once iOS work moves beyond initial scaffolding into iterative shader / map-renderer tweaking, where the inner loop is "edit Rust, see the visual change."
- **Centralize design tokens in a single source of truth with codegen to per-platform files.** Today each platform hand-maintains its own design-token file: `web/style/tokens.css` (CSS custom properties), `ios/EaforaApp/DesignTokens.swift` (Swift extensions), Android equivalent when that lands. Changing a value (the red, the spacing scale, the body type size) means editing each file, with no compiler-checked guarantee they agree. Replace with a single `docs/design/tokens.json` (or YAML) holding `{token-name: value}` entries; add a build-time codegen step that reads it and emits each platform's file: `web/build.rs` writes `tokens.css`; an iOS pre-build script writes `DesignTokens.swift`; `core/build.rs` writes `core::design` Rust constants if/when the wgpu renderer needs them (e.g. choropleth fill colors). Token JSON becomes the canonical source; per-platform files become generated artifacts (gitignored). **Trigger:** the token set grows past hand-syncable size — probably v1.5+ when hover states, focus rings, animation timings, and more semantic colors land. v1's token set is small enough (handful of colors, four-step spacing scale, two fonts) that the codegen overhead doesn't earn its keep yet.
- **iOS App Intents (Siri / Shortcuts) for region-and-statistic lookups.** Apple's App Intents framework lets a user say "Hey Siri, what's Japan's TFR?" and get an answer without opening the app, or build Shortcuts that chain Eafora data into automations. The shape: declare `AppIntent`-conforming structs with the parameters (region, statistic), implement `perform()` to query `core::*` and return a string or rich response, register the intents in the app's metadata. Cheap to add once we have the `core::canonical` lookups stable; not built v1 because we haven't validated user demand. **Trigger:** a TestFlight tester or App Store reviewer asks for Siri integration explicitly, OR App Intents becomes a marketing differentiator we want to advertise. App Intents is also the foundation for future widget interactivity and Spotlight integration if we ever want them.
- **Enable MSAA (multisample anti-aliasing) on the map render pipelines.** v1 builds both render pipelines with `multisample: count 1` (no MSAA), so triangle and line edges — country outlines and coastlines — rasterize with hard per-pixel coverage and show stair-stepping. It is most visible on the design's crisp hairline borders. Enabling it means allocating the surface's color target as a multisampled texture (e.g. `count: 4`), setting `MultisampleState.count` to match in both pipelines, and adding a resolve target that averages the multisampled image down to the presentable surface. Costs a multisampled color texture in memory plus the per-frame resolve. **Trigger:** edge aliasing on borders/coastlines reads as a visible-quality problem once the map renders real geometry on-device.
- **Inertial (momentum) pan for the map camera.** Manual pan (C3.3) tracks the cursor 1:1 and stops the instant the drag ends — event-driven, no animation loop. Inertial pan would let a fling keep gliding after release, its velocity decaying over time. Because the motion continues with no further input, it needs the same time-driven self-scheduling `requestAnimationFrame` loop as animated zoom-to-country (C3.4): decay the pan velocity each frame and redraw until it falls below a threshold, then stop. **Trigger:** manual pan ships and the interaction reads as wanting momentum, or a user asks for it.
- **Cross-platform pinch-zoom classification.** A trackpad pinch and a real Ctrl+mouse-wheel both arrive as a wheel event with `ctrlKey` set. `handle_wheel` (`web/src/map/canvas/driver.rs`) distinguishes them by delta shape — a pinch is treated as such only when `ctrlKey` is set, `deltaMode` is pixel, and `|deltaY| < TRACKPAD_PINCH_MAX_DELTA` (50) — so a pinch gets `TRACKPAD_PINCH_ZOOM_SENSITIVITY` (0.006) while a real Ctrl+scroll or line/page-mode wheel falls through to the ordinary `WHEEL_ZOOM_SENSITIVITY`. The `50` threshold and the pixel-mode assumption are heuristics verified on a Mac trackpad only; a non-Mac trackpad, or a mouse whose pinch/notch deltas straddle the threshold, could misclassify (a fast pinch reading as a wheel, or a gentle Ctrl+scroll as a pinch). **Trigger:** pinch-zoom or Ctrl+scroll is tried on a non-Mac device and misclassifies — retune the threshold, or add `deltaMode`-aware normalization.
- **Shareable deep-link URLs encoding the map view state.** Encode the current view — selected region, statistic kind, active period, and optionally the camera (`Viewport` center + zoom) — into the URL so a shared link reproduces that exact view. On load the driver seeds `FrameState` (`active_statistic` / `active_period_start` / `selected_region`) and the `Viewport` from the parsed URL instead of the home defaults; on any view change it writes the state back into the URL (throttled), so copying the address bar shares the current view with no round-trip. Web is the natural home: a URL fragment (`#...`) plus the History API updates the link without a reload. Mobile reuses the same encoding behind universal links / app links (iOS associated domains, Android app links) so a shared link opens the app to the same view and falls back to the web app when the app is not installed. Reuses the `RegionCode` / `StatisticKind` / period already in `FrameState`, and the `Viewport` as the single camera-state source. Prerequisite for social sharing, and it pairs with the share-image feature below (the image carries a "view this live" link). Sub-decisions deferred: fragment vs. query string; whether to version the encoding; whether a stale code (a region or period absent from the loaded bundle) degrades to the nearest valid view rather than erroring. **Trigger:** social sharing becomes a priority, or the share-image feature below is picked up (it wants a companion link).
- **Shareable image generation (share-card capture mode).** Produce a shareable image of a focused view — a zoomed map around a country with the detail card (region, statistic, value, source) and the legend composited over it, as in the share-card mock. Two shapes, not mutually exclusive: (a) *programmatic* — render the map to an offscreen wgpu target at a fixed share resolution (e.g. 1200×630 for an Open Graph preview image), composite the card and legend, read the pixels back, and encode a PNG for download or the Web Share API; because the composition is deterministic from a view-state it pairs with the deep-link encoding above and could even run headless server-side to generate link-preview images. (b) *interactive capture mode* — a special view that enlarges the chrome and map and lets the user pan and zoom to frame the shot before exporting, so they control exactly what appears. Web is easiest (read back the existing wgpu surface or an offscreen render target; download or `navigator.share`). Mobile is feasible but lower priority: render to a texture and hand the image to the platform share sheet through the UniFFI boundary. Reuses the renderer, the `Viewport` camera, and the `SelectionView` the detail panel already builds. Sub-decisions deferred: fixed preview dimensions vs. user-chosen aspect; client-only readback vs. a headless server renderer for link previews; whether the exported card reuses the live detail-panel layout or a separate export template. **Trigger:** social sharing is prioritized; likely picked up alongside or just after the deep-link URLs.


- **A second chart in the detail dock, and the statistic that earns it.** The dock draws one chart, a line of the active statistic's series, and that shape suits every statistic ingested so far because each is one number per region per period. A population pyramid is a different shape: an age-and-sex distribution, drawn as the conventional back-to-back horizontal bars. It belongs to a statistic the store does not yet carry, plausibly net population change, and it appears as a second chart beneath the line rather than instead of it, so the reader sees the rate and the age structure it acts on together. Two pieces of work, in order. First a source and a canonical shape for a distribution: no ingested source carries population by age and sex, and a distribution is not the scalar `(region, statistic, period)` cell the store holds, so the schema question is the real work here (the United Nations Population Division's World Population Prospects is the obvious source, publishing single-year age structures by sex for every country). Then the dock learns that a statistic can bring its own chart, which means the chart is chosen by statistic rather than assumed. The pyramid itself is straightforward once both exist. **Trigger:** a population-by-age source is ingested, or a statistic lands whose series a line chart misrepresents.


- **Diagnose and handle the Telegram in-app browser, which loads forever instead of reporting a failure.** Opening `app.eafora.org` in Telegram's iOS in-app browser leaves the "Loading data." overlay on screen indefinitely; no map appears and neither the unsupported nor the data-unavailable panel replaces it. Two hypotheses, both consistent with the symptom and not yet distinguished. (a) The client-side WASM never takes over: the deploy is static assets from `target/site` (`web/wrangler.toml`), and the prerendered `index.html` already contains the `Loading` overlay because `RenderStatus` starts at `Loading` and the server build never runs the renderer (`web/src/map/canvas/canvas.rs:62`), so a WASM bundle that fails to fetch or instantiate produces exactly this screen with no Rust code running to report anything. (b) The startup chain hangs: `render_status` is written only after `set_up_driver` resolves (`web/src/map/canvas/driver.rs:596`), so any await inside it that never settles rather than rejecting leaves the panel up forever. Candidate stages, each an unbounded await: OPFS root and persistence (`OpfsArtifactCache::create`), the embedded-bundle load, `request_adapter` / `request_device`, and `attach_surface_from_canvas`. The startup path distinguishes only failure modes that produce an error; the hang is the gap. Work splits into finding out which hypothesis holds (remote-debug the in-app WKWebView from Safari's Develop menu, or check whether any client log line is reached), then the fix: a deadline on the first-paint chain that turns a stalled stage into a panel naming the stage, plus whatever the actual cause needs. **Trigger:** a public launch, or Telegram/other in-app browsers (Instagram, X, Facebook) become a meaningful share of arrivals — a link shared in a chat is a likely path to the app, so this is more reachable than it looks.

- **Run without persistent storage instead of refusing to start.** Safari's private browsing rejects `navigator.storage.getDirectory()` with `UnknownError: The operation failed for an unknown transient reason`, and `OpfsArtifactCache::create` maps any such failure to `StartupError::BrowserUnsupported`, so the client shows the unsupported panel and draws nothing in a mainstream browsing mode. The panel is right for a browser with no OPFS at all, which is what it was written for, but private browsing is a capable browser denying persistence rather than a browser missing a capability, and nothing about drawing the map needs storage that survives a reload. The obstacle is that the cache sits on the critical path: `load_embedded_bundle` writes each file with `cache.put` and `Bundle::open` reads them back, so dropping writes would leave nothing to open. The fix is a session-memory mode on the same type, holding the bytes for the session so the loader's signatures do not change, and reserving the unsupported panel for a missing wgpu backend, which genuinely is required. Costs holding a bundle's bytes in memory alongside the parsed form, and reverses the "no fallback" wording in `specs/003-web-client/quickstart.md` and the spec. Reach is narrow: it affects private browsing and any other mode that denies persistence, not ordinary sessions. **Trigger:** a public launch, or the first report from someone who hit it.

- **Compare regions side by side, from a plus control on the detail panel.** A reader looking at Poland's collapse wants Hungary's beside it, and today the only way is to remember one figure and click the other. A plus in the detail panel's header would open a second panel for another region, and the interesting version of this is not two panels but one chart: the series overlaid on a single plot, which is exactly what the design language reserves blue for (`docs/design/README.md` §Color, "secondary series in a multi-line chart"). Four things it needs, roughly in order of how much they change.

  First, the selection stops being singular. `FrameState.selected_region` is an `Option<RegionCode>` and `SelectionView` carries one region's cell, series, rank, and sources; comparison makes both of those collections. That decides several things downstream that currently have one obvious answer: which region the map outlines in red when two are selected, whether a third click adds or replaces, and what the summary panel shows when it has room for one figure and two are chosen.

  Second, the chart becomes a multi-series chart. The single-line plot in `web/src/map/detail_panel.rs` scales its vertical range to one region; two regions need a shared range, a way to tell the lines apart that is not two saturated colours competing on white, and a decision about whether the reference line and the active-period marker are drawn once or per series.

  Third, the layout. The dock is 445px against a 1440px viewport, so two of them side by side take 890px and the map stops being the subject. The alternatives are a taller dock holding stacked figures above one shared chart, or a dock that widens to hold two columns, and on a phone neither works: the bottom sheet has room for one region, so comparison there is probably a switch between them rather than both at once.

  Fourth, the URL. `docs/architecture/client-web.md` §Routing and SSG fixes `/region/<code>/<statistic>/<year>` on the principle that the region identifies the page while the statistic and year are view state on it. Two regions are two subjects, so a comparison does not fit that shape: either the region segment becomes a list (`/region/deu+pol/tfr/2024`) or comparison gets a route of its own (`/compare/deu,pol/tfr/2024`). Whichever it is, the choice also decides whether comparisons are prerendered at all, since the pair count is the square of the region count and 217 regions make 46,872 ordered pairs. **Trigger:** the detail dock has shipped and a reader asks for two regions at once, or the deep-link work below is picked up and it is cheaper to settle the URL shape for both at the same time.
- **Adopt Nix (or `devenv` / `flake.nix`) for reproducible local development.** The current bootstrap is `setup.sh` plus Homebrew, with most tool versions floating across `brew update` cadences (Postgres point release, dbmate, system OpenSSL/rustls linkage, etc.) and Rust pinned only by each developer's `rustup default`. Eafora is single-contributor today so the drift hasn't bitten, but a second contributor or a CI environment would surface it immediately. Decision criteria, candidate tools (flakes, `devenv`, `nix-direnv`, Brewfile fallback), and what to investigate are captured in `docs/research/nix-reproducible-dev.md`. **Trigger:** a second contributor needs to set up the repo, OR `setup.sh` breaks on a point-release float, OR CI gains a pinned-toolchain requirement.
- **Retain `.xcarchive` files for shipped iOS builds when rebuild-from-source determinism breaks.** Current policy (per `docs/architecture/client-ios.md` §Archive retention) is: don't retain archives; rely on the git revision recorded in the binary's `Info.plist` to enable `git checkout <revision> && xcodebuild archive` for crash-report symbolication, with the rebuilt `.dSYM` UUIDs matching the original. This relies on build determinism that probably won't hold long-term — Xcode toolchain updates, Rust toolchain updates, dependency bumps, and Apple Silicon's nondeterminism in some optimization passes can all break it. (Even Nix shells help only with the toolchain layer; LLVM/Swift codegen can still vary across runs.) When it breaks, the recovery path is to retain `.xcarchive`s for any build that goes to TestFlight external or App Store — approx. 100 MB per archive, 1-2 archives per month, low-single-digit-GB/year storage on the Mac mini. The Mac mini's regular backup captures them. **Trigger:** the first time a real crash report from a shipped build can't be symbolicated by `git checkout && rebuild` (rebuilt `.dSYM` UUID doesn't match the original). At that point, switch to retain-then-symbolicate; the missed archive that prompted the policy change is the one we have to write off.

- **Serve a 404 page.** `web/wrangler.toml` leaves `not_found_handling` unset, so an unmatched path returns a bodyless 404. That is the right default while the deploy is the map route plus artifact files: the `single-page-application` setting would answer a mistyped shard URL with `index.html` at 200, handing the artifact loader an HTML document instead of the 404 it knows how to report. A styled page is still worth having for a human who mistypes a URL, which means producing `404.html` in the build and switching the setting to `404-page`. Both the export step and `_headers` would need to cover it. **Trigger:** the SSG `/region/<code>` and `/about` routes land, since a wrong region code then becomes a plausible way for a person to arrive at a missing path.

- **Compress the artifacts in the producer, and decompress them in `shared`.** Neither CDN compresses them for us. A probe deploy against Cloudflare Workers Assets confirmed it serves a response compressed only when the content type is on a fixed list holding no generic binary type, so a 1.5 MB FlatGeobuf file came back whole with no `Content-Encoding`; R2, which serves the live bundle, does not compress on its own either. The artifacts compress well: the geometry 3.4x (1,576,240 to 468,347 bytes) and a statistic shard 13.0x (2,125,824 to 163,503), and the shard's 13x is real redundancy rather than reclaimable slack, since its page count times page size equals its file size exactly and its freelist is empty. Compressing in ingestion and decompressing in the client is the only option that also covers iOS, Android, and any future CDN. It needs a decoder in `shared`, a producer change, and a decision on whether the manifest hash covers compressed or decompressed bytes. Uploading `.br` siblings is not an alternative and was withdrawn as spec FR-005. Measured saving at current artifact sizes: approx. 3.07 MB per cold fetch. **Trigger:** artifact growth pushes second paint toward its 8 MB target, or the native clients start fetching the live bundle over a metered connection.
