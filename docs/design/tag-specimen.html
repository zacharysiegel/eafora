Tag

A 1px-bordered rectangle around one uppercase word, carrying a categorical value. Extracted from the region-detail availability table, where it distinguished what the client can render today from what needs producer work. Kept here so the idiom is reusable rather than re-invented.

Variants

DEFAULT Rule grey. The neutral case: a value with no weight of its own.
NOW Ink. Affirmative: present, available, final.
PRODUCER Red. The exception that wants attention: missing, blocked, provisional.
SOURCE Blue. Reserved, per the colour rules, for a source citation or a secondary series.

Why it works here

It is the same construction as every other surface in the product: an opaque white fill, one hairline border, square corners, no shadow. It reads as a small sheet, which is the metaphor the whole interface runs on. And because the border carries the state rather than a fill, a red tag draws the eye without introducing a saturated block that would compete with the map.

The type is 10px, deliberately below the smallest type token. A tag is a label on a value, never the value, so it should not match the weight of the text it annotates.

Do not

Round it
PROVISIONAL A pill radius contradicts square corners. --radius-default is 0, and the larger the element the closer to zero.
Fill it
PROVISIONAL A saturated block competes with the map's data colour, which is meant to be the only saturated thing on screen.
Put a sentence in it
Subject to revision by the source A tag holds one categorical word or two. Prose belongs in the line beside it.
Use it for a number
218 Numbers are tabular figures in running text, not boxed. A box says "category".

If it ships

Add .tag and its three modifiers to a component stylesheet under web/style/components/, reading every value from the existing tokens. The 10px size and the 0.06em tracking are the only two numbers here that are not already tokens; promote them if a second component wants them.
